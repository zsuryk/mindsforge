# Platform preview canvas replaces text-only hooks card

The "Platform hooks" card in the clip studio sidebar is replaced with a visual preview canvas that renders platform-native frames for each surface. The decision addresses three gaps: (1) the backend generates rich structured feature manifests (polls, quizzes, overlays, stickers, chapters, thumbnail briefs) but the frontend reduces them to copyable text blocks, (2) the README promises platform-adapted content but the hook pane shows plain strings, and (3) creators cannot see what their content will look like on each platform before publishing.

**Why a visual canvas instead of richer CopyBlocks:** The features are inherently visual — a poll is a card with options, an overlay is text at a position, a sticker is an emoji at a placement. Rendering them as text loses the spatial and structural information that makes them useful for previewing. A visual canvas communicates the concept faster than a text description.

**Why client-side rendering instead of backend-rendered preview images:** The hackathon timeline favors iteration speed. Client-side React components interpret the feature JSON directly — no new backend asset pipeline, no image generation latency, and the components render live during demos. The previews don't need to be pixel-perfect; they need to communicate the concept. Backend-rendered images could be a future enhancement for higher fidelity.

**Why fixed sidebar width with scaled previews:** The sidebar is 1/3 width on desktop. Scaling previews to fit (pillarboxing vertical, letterboxing horizontal) keeps the layout stable when switching tabs and preserves the "see hooks next to the video" proximity that ADR-0004 established for the sticky rail. Alternative layouts (resizable sidebar, full-width below) either shift the layout or break the proximity.

**Why surface-specific components instead of a composable system:** Each platform surface has a fundamentally different visual structure — a YouTube poll card shares no UI primitives with a TikTok vertical canvas or a tweet mockup. Building shared primitives upfront would require guessing the abstraction boundaries. Starting with surface-specific components (YouTubeShortsPreview, TikTokPreview, etc.) and extracting shared primitives later if patterns emerge is pragmatic for a hackathon. The components are small enough that duplication is acceptable.

**Why copy-in-preview:** The preview replaces the hooks card, which was purely read-only. Adding copy icons to visual elements (hooks, poll questions, captions) makes the preview self-contained for quick grabs. Non-visual features (tags, hashtags, captions, shorts_link) remain as CopyBlock panels in the adaptation studio because they don't benefit from visual rendering.
